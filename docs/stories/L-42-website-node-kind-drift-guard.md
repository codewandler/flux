# Website node-kinds/prelude tables — generate + drift-guard like the skills

## Goal
The node-kind and prelude-type tables have one source of truth (`flux_lang::schema::
node_kind_catalog()` / `prelude_type_catalog()`) and four drift-guarded consumers (planner prompt,
reference.md, both SKILL.md files) — but the public website's copies
(`website/docs/language/node-reference.md`, `overview.md`) are manual mirrors with no markers and
no test. Extend the existing `skill_in_sync` machinery to the website pages so a new node kind or
edited doc-comment cannot ship with a stale public site.

## Acceptance
- [x] The website tables live between `<!-- BEGIN/END generated:node-kinds -->` (and
      `generated:prelude-types`) markers, regenerated by the same `UPDATE=1` flow as the skills
      (`UPDATE=1 cargo test -p flux-lang --test skill_in_sync`, or a sibling test if path layout
      argues for one).
- [x] Failing-first: the sync test fails on a hand-edited table before the regeneration lands.
- [x] AGENTS.md's "Keeping the Flux-Lang language and its docs in sync" section lists the website
      pages among the generated consumers.

## Progress
- Corrected the story's premise on the *second* mirror: `overview.md` carries no node-kind or
  prelude table (grepped the whole `website/docs/language/` tree for `kind | description` /
  `type | description` — only two hits). The real second mirror is
  `website/docs/language/types-and-effects.md` (`## Prelude artifact types`), a Docusaurus page
  `overview.md` links to but does not duplicate. Guarded that file instead.
- New sibling test `crates/flux-lang/tests/website_in_sync.rs` (a sibling of `skill_in_sync.rs`,
  since it targets two different files with two different marker pairs rather than one file):
  `website_node_reference_node_kinds_block_is_in_sync` (targets `node-reference.md`) and
  `website_types_and_effects_prelude_types_block_is_in_sync` (targets `types-and-effects.md`).
  Same `<!-- BEGIN/END generated:node-kinds -->` / `generated:prelude-types` markers, same
  `UPDATE=1` env-gated regeneration as `skill_in_sync.rs`.
- Refactored `flux_lang::schema::node_kind_catalog()` and `flux_lang::prelude::prelude_type_catalog()`
  to build from new public row-accessors (`node_kind_rows()` / `prelude_type_rows()`, returning
  `Vec<(String, String)>`) instead of assembling the markdown table directly. This is the "shared
  generator helper" the website test needed: Docusaurus's markdown/MDX table parser treats an
  unescaped `|` inside a cell as a new column boundary (unlike the plain-markdown crate docs and
  skills, which tolerate it), so the website generator escapes `|` to `\|` per row — a
  per-consumer rendering difference, not a content difference, matching the existing
  reference.md-vs-SKILL.md precedent of same content / different surrounding template.
  `node_kind_catalog()`/`prelude_type_catalog()` output is unchanged (still verbatim, still
  covered by the existing `skill_in_sync`/`schema`/`prelude` tests).
- **Failing-first, before wiring markers**: added the `<!-- BEGIN/END -->` markers around the
  *existing* hand-maintained tables and ran `cargo test -p flux-lang --test website_in_sync`
  against them unmodified — both tests failed, catching real drift:
  - `node-reference.md`: several rows had been hand-condensed vs. the doc-comment source (e.g.
    `peek`'s description said "or null if the symbol is not yet bound" on the site vs. "or an
    empty string if the symbol is not yet bound" in the actual `Node::Peek` doc-comment — a
    substantive behavioral-description mismatch, not just wording), plus unescaped `|` was already
    manually escaped by hand (`\|`) in several rows (`retry`, `confirm`, `expr`, `fmt`).
  - `types-and-effects.md`: the `Blocked` row read `` same shape as `Answer` `` (site) vs. the
    source doc-comment's rustdoc intra-doc link `` same shape as [`Answer`] `` — the site had
    hand-stripped the `[...]` link brackets.
  Regenerated with `UPDATE=1 cargo test -p flux-lang --test website_in_sync`; re-ran plain —
  green. Net effect: the website tables now carry the *raw* doc-comment text (verbatim, same as
  reference.md/SKILL.md) rather than a hand-condensed paraphrase; the only per-consumer difference
  is the required `\|` escaping. This does mean the previously "lightly condensed" website prose
  is gone in favor of one non-divergent source of truth — the explicit point of the story.
- AGENTS.md: extended the existing paragraph in "Keeping the Flux-Lang language and its docs in
  sync" to name `website/docs/language/{node-reference,types-and-effects}.md` as consumers (e), and
  added `UPDATE=1 cargo test -p flux-lang --test website_in_sync` alongside the other two
  regeneration commands. Edited only that paragraph; re-read the file fresh first since another
  agent had touched an unrelated line (an `flux-audio` L0-crate table row) earlier the same day.
- Gate: `cargo test -p flux-lang` (247 tests incl. the 2 new ones) green, `cargo clippy -p
  flux-lang --all-targets -- -D warnings` clean, `cargo fmt -p flux-lang` applied/clean. Also ran
  `cargo check -p flux-flow` (unaffected consumer of the refactored `schema`/`prelude` helpers) —
  clean.
