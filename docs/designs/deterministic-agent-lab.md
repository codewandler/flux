# Deterministic Agent Lab — Test · Tune · Resurrect

**Status:** proposed (2026-07-15). **Pillar:** Agent (SDK). **Epic:** `deterministic-agent-lab`
(stories D-174…D-180). **Owner surface:** `crates/flux-sdk` (`codewandler-flux-sdk`), with one
shared primitive in `crates/flux-flow`.

> This design was produced as a forward-looking "killer feature" exploration and is not scheduled
> against the current in-flight epics (live-datasource D-168…D-173, harness-hardening C-76…C-88).
> Story IDs are provisional and may need reconciliation if a concurrent session allocates D-174+.
> The board is intentionally **not** regenerated by this change.

## Why

flux's founding thesis is *the LLM is not the runtime*. Every turn's plan is persisted as
canonical, re-parseable Flux-Lang source (`PlanAttempted.plan_source`, invariant
`parse(format(ast))==ast`), and every leaf-op dispatch's redacted output is recorded in an
append-only cassette (`RunEvent::OpRecorded`, `crates/flux-flow/src/cassette.rs`). That makes **a
flux run a deterministic artifact** — re-runnable offline, at ~$0, with side effects never
re-firing and a loud divergence guard on any hidden nondeterminism.

The Time Machine (C-43/A-45/A-46/C-44) turned that substrate into three *debugging* verbs —
`Session::replay`, `Session::fork`/`inject`/`edit`/`diff`, and `run_diff`. What it did **not** do is
turn the substrate into a **product for people who embed `flux-sdk`**. Measured against what an
agent SDK consumer actually needs day-to-day, three structural gaps remain — and each is something
*no LLM-as-runtime SDK can close*, because their only run artifact is an opaque, nondeterministic
transcript:

- **No way to TEST an agent.** Every competing SDK (LangGraph, CrewAI, OpenAI Agents SDK, Claude
  Agent SDK) forces a choice between calling the live model (nondeterministic, costs money, flaky)
  or hand-mocking it (you test your mocks, not your agent). flux persists a canonical, re-parseable
  **plan** and a redacted op **cassette**, so it alone can re-run the *real* agent offline for $0 and
  assert on *how it reasoned*.
- **No way to safely EXPERIMENT.** "Should I ship this model/prompt/policy change?" is answered
  today by two noisy live samples against ever-moving APIs. flux can re-run a recorded session under
  exactly one changed variable with the rest of the world **byte-frozen** — a controlled experiment.
- **No way to make an agent CRASH-PROOF.** Long-running engineering-ops agents (the stated broader
  market) get OOM-killed and redeployed mid-task. Every LLM-as-runtime SDK re-calls the model on
  restart (re-spend + a *different* plan) and re-fires side effects. flux has the plan as durable
  source *and* every completed op in a cassette *and* a deterministic substrate — the three exact
  ingredients transparent zero-respend, exactly-once resume requires.

An ideation → adversarial-judge exercise (6 proposals, 3 judges) converged unanimously on the test
kit as the headline, with crash-resume and counterfactual A/B as the strongest siblings. They share
one substrate, so they ship as one product with one sentence:

> **Because a flux run is a deterministic artifact, flux is the only agent SDK where your agent is
> testable (Test), tunable against a frozen world (Tune), and crash-proof (Resurrect).**

## Shape decision: three doors on one substrate

The three doors are ergonomic surfaces on the existing `Session`/`Client` handles plus one new
test-only module. **No new client type** (consistent with the sdk-surface decision):

| Door | Surface | Pillar value |
|---|---|---|
| **Test** | `flux_sdk::test::Scenario` (feature `test-kit`) | Auditability, quality-over-quantity |
| **Tune** | `Session::what_if()` / `Client::what_if_over()` | Determinism, repeatability |
| **Resurrect** | `Session::resurrect()` / `ClientBuilder::auto_resurrect` | Reliability (ops market) |

## The unifying spine: a cassette-scope family

All three doors are one small generalization of a single existing engine primitive. Today
`crates/flux-flow/src/cassette.rs:119`:

```rust
pub enum CassetteScope { Record(RecordScope), Replay(ReplayTape) }
```

is installed on the `FlowStore` at a **single** point (`engine.rs:420`,
`set_cassette(Some(...Record...))` at turn start) and consulted at the **one** dispatch chokepoint
`ExecutorHost::dispatch` (`crates/flux-flow/src/runtime.rs`: Record arm `:88`, Replay arm `:110`,
Replay-only confirm auto-allow `:158`). We add two arms and make the enum `#[non_exhaustive]` so any
future arm is additive:

- **`Frozen(FrozenTape)`** — serve every op from a `ReplayTape` (the byte-frozen recorded world),
  with optional per-op **substitutions**; on a miss either latch-and-halt (hermetic) or fall through
  to a live `RecordScope` (live-bridge). Powers **Tune** and the Test Kit's world-pinned re-plan.
- **`Resume(ResumeTape)`** — serve *completed* ops from tape (exactly-once, non-latching on a plain
  miss), fall through to live `executor.dispatch` + record for the crash tail. Powers **Resurrect**.

Plus one matcher variant: `ReplayTape::serve_nonlatching(op, input) -> Option<OpOutcome>` — the same
dual-hash matcher as `serve`, but a *plain* miss returns `None` without latching divergence
(truncated cells and a hash-mismatch-after-match still latch loudly).

This is the only change to the safety-critical engine, and it obeys **no-fallbacks / clean-cutover**:
the model-re-invoking path is `run_turn_pinned`, which reuses the entire `run_turn` body and swaps
*only* the `set_cassette` install — never a parallel turn path.

## Door 1 — Test (`flux_sdk::test`, headline)

New module behind a default-off `test-kit` cargo feature (keeps the default build
dependency-free, matching `providers`/`pricing`/`plugins`).

**Fixture format.** A `Scenario` is a `Storage::dir` directory (`tests/scenarios/<name>/`:
`events.db` + `flow.db`, so it is *also* openable by `flux replay`/`flux sessions`) plus a
`model.jsonl` model cassette. Redacted-by-construction — cassette cells and `plan_source` are
already scrubbed through the same `Redactor` (C-22), so goldens are safe to `git commit` with no
extra work.

```rust
pub struct Scenario;
impl Scenario {
    pub async fn record(client: &Client, input: &str, path: impl AsRef<Path>) -> Result<Scenario>; // live, once
    pub fn load(path: impl AsRef<Path>) -> Result<Scenario>;                                        // $0, offline
    pub async fn replay(&self) -> Result<Outcome>;               // Engine 1: hermetic; the CI guard
    pub async fn check(&self, client: &Client) -> Result<Report>;// Engine 2: world-pinned re-plan
    pub async fn inject_at(&self, node: u32, error: &Value) -> Result<Counterfactual>; // fault injection
}
impl Outcome {   // assertions panic with a rendered plan-source + world diff
    pub fn assert_plan_snapshot(&self);          // insta-style .flux.snap on canonical Flux-Lang
    pub fn assert_calls(&self, ops: &[&str]);
    pub fn assert_never_calls(&self, op: &str);  // SAFETY: "my agent never runs shell.exec"
    pub fn assert_text_contains(&self, s: &str);
    pub fn assert_cost_under(&self, usd: f64);   // via Session::cost
    pub fn assert_faithful(&self);               // no ReplayTape divergence
}
impl Counterfactual { pub fn assert_compensated_with(&self, op: &str); pub fn assert_diverges_at(&self, node: u32); }
```

Re-baseline like cargo-insta: `FLUX_GOLDEN=update` re-records against a live client and rewrites the
fixture.

- **Engine 1 `replay()`** wraps the shipped `replay_session` (`crates/flux-flow/src/replay.rs`):
  faithful, model-free, IO-free, side-effect-free — the always-on CI guard, safe to run with a
  deny-all approver and a never-called provider (proven by D-156's `NeverMock` pattern).
- **Engine 2 `check()`** installs `CassetteScope::Frozen(golden_tape)` on a `run_turn_pinned` call
  and re-drives the *real* agent loop with the client's *current* prompt/model/tools against the
  frozen world, then `run_diff`s the result vs the golden into a `Report`. `DiffRow::Plan` ⇒
  reasoning regression; `DiffRow::Output`/latched divergence ⇒ world regression (`projection.rs:573`).
- **Fault door** wraps `Session::fork(at).inject(err)` + `Fork::diff`, mapping saga-compensation
  `RunEvent`s in the tail to `assert_compensated_with`.

## Door 2 — Tune (`Session::what_if()`, counterfactual A/B)

Re-run a recorded session under **exactly one changed variable**, world byte-frozen, so the diff is
a pure causal readout.

```rust
impl Session { pub fn what_if(&self) -> WhatIf; }              // this session = the frozen world
impl WhatIf {
    pub fn turn(self, n: usize) -> Self;
    pub fn model(self, m: impl Into<String>) -> Self;          // re-plan under a different model
    pub fn system_prompt(self, p: impl Into<String>) -> Self;  // re-plan under a different prompt
    pub fn policy(self, perms: Permissions) -> Self;           // re-authorize under a different policy
    pub fn substitute(self, op: &str, output: Value) -> Self;  // swap one op's recorded output (pure, no model)
    pub fn substitute_at(self, node: u32, output: Value) -> Self;
    pub fn off_tape(self, mode: OffTape) -> Self;              // Halt (hermetic) | Live (bridge to real IO)
    pub async fn run(self) -> Result<Counterfactual>;
}
impl Counterfactual {
    pub fn session(&self) -> Session;                 // itself replayable / forkable
    pub fn diff(&self) -> Result<RunDiff>;
    pub fn first_divergence(&self) -> Option<Divergence>;
    pub fn hermetic(&self) -> bool;                   // stayed entirely on tape
    pub fn cost(&self, p: &PricingTable) -> Result<Vec<ModelCost>>;
}
impl Client { pub async fn what_if_over(&self, sessions: impl IntoIterator<Item=String>, change: WhatIfSpec) -> Result<SweepReport>; }
```

Re-derivation reuses `replay_prefix` (`crates/flux-flow/src/fork.rs`) to rebuild state to the target
turn into a correlated new session, then re-drives one turn with the `Frozen` scope. Variables ride
shipped seams: `switch_model_for_session` (`engine.rs:349`, model), a throwaway engine via
`assemble_with_loop` (`engine.rs:248`, prompt), an executor rebuilt from `Permissions` (policy). A
pure `substitute` needs no model call at all.

**Honesty is a hard requirement, not a caveat.** Pure `substitute` is fully offline and produces a
*complete* diff; agent-config variants (`model`/`prompt`/`policy`) are hermetic only for the prefix
they don't perturb — the moment a re-plan reads a different input, that op's `input_hash`
legitimately misses the tape (that IS the causal boundary). The API must report `hermetic=false` and
localize, never fake a complete diff.

## Door 3 — Resurrect (`Session::resurrect()`, durable execution)

Transparently finish a turn killed mid-execution (OOM/redeploy/crash) from the exact crash point.

```rust
#[non_exhaustive] pub struct InterruptedTurn { pub turn_id: i64, pub plan: DraftAst, pub completed: usize, pub started_at_ms: i64 }
#[non_exhaustive] pub struct ResurrectReport { pub statements_fast_forwarded: usize, pub ops_served_from_cassette: usize, pub ops_run_live: usize, pub output: TurnOutput, pub diverged: Option<String> }
impl Session {
    pub fn interrupted(&self) -> Result<Option<InterruptedTurn>>;  // detect via turns() ended_at_ms==None
    pub async fn resurrect(&self, sink: &mut dyn AgentSink) -> Result<Option<ResurrectReport>>;
}
impl ClientBuilder { pub fn auto_resurrect(self, on: bool) -> Self; }  // default on for Storage::dir
```

New driver `crates/flux-flow/src/resurrect.rs` (~200 LOC, modeled on `replay.rs`/`fork.rs`): find the
open turn (`turns()` `ended_at_ms==None`), fetch its accepted plan via `plans_by_key`
(`replay.rs:82`), rebuild the ledger via a new `ResumeLedger::from_interrupted` (the existing `fold`
gather of `StatementCompleted` rows *without* requiring an open `PlanHalted` latch — the one line
today's crash-conservatism blocks; `crates/flux-lang/src/runtime.rs:676`), install
`CassetteScope::Resume`, call the shipped `execute_flow_resumable_with_composites`
(`runtime.rs:338`) on the **same** session (unlike replay's scratch store / fork's new session), then
`end_turn` to write `TurnEnded`. `request_approval` under Resume uses the **real** approver — the
live tail still gates.

**Exactly-once is honest, not absolute** (documented, mirroring Temporal activity semantics): an op
interrupted *during* dispatch (side effect fired, process died before `record_cell`) has no cell and
re-fires live on resume — at-least-once for that one op, exactly-once for every op with a recorded
cell. Guard: a served cell whose re-derived `input_hash` mismatches latches `ReplayDiverged` loudly.

## CLI surface (thin, on the same SDK)

Per the vision (the CLI is the reference app built on the SDK): `flux record <name> "<prompt>"`
(writes a `tests/scenarios/<name>/` fixture), `flux test [<name>]` (runs `Scenario::replay` +
assertions, offline, $0), and resurrect-on-open (`flux sessions` resumes an interrupted turn when
`auto_resurrect` is on). Fixtures are plain `Storage::dir` dirs, so `flux replay`/`fork`/`diff`
already open them.

## Safety, invariants & layering

- **The one envelope stays non-bypassable.** No new path skips authorization → approval → guarded
  IO. Replay/Frozen-hermetic serve from tape (no dispatch at all); Resume and Frozen-live-bridge tail
  dispatches go through the real `Executor` with the real approver.
- **Policy-mode authorize/execute split** (Tune's hardest surgery): a stricter policy's DENY must
  surface as divergence, not be masked by a taped output — this needs an authorize-*only* entry
  (`Executor::dispatch_outcome` currently bundles authorize+execute). Deferred to its own story
  (D-177); the rest of Tune ships without it.
- **Redactor parity.** Fixtures record redacted cells; assert-time must use the same redactor config
  or the dual-hash matcher drifts — pin the redactor into the fixture.
- **Truncated cells** refuse hermetic service by design (`cassette.rs:296`); the kit reports
  "re-record with a larger `FLUX_CASSETTE_MAX_BYTES`" as an actionable error, and `assert_faithful`
  treats it as a diagnostic, never a flaky pass.
- **Portable-golden re-import fidelity** is the sharpest correctness risk: injecting recorded events
  into a fresh store must preserve ordering so value ids stay rowid-insertion-order and the
  forward-scan matcher behaves identically — covered by a capture→save→load→replay round-trip
  property test.
- **SemVer / layering.** Adding variants to the public `CassetteScope` is **breaking → MINOR** (0.y)
  per the flux SemVer rule; everything else is additive (`#[non_exhaustive]` output structs). No new
  crate; the test kit is a `flux-sdk` module. `flux-flow` (L3) and `flux-lang` (L0) changes respect
  the layer map — the codegate lint stays green.

## Non-goals (v1)

- Re-litigating the shipped time-machine verbs (`replay`/`fork`/`diff`) — the Lab *uses* them.
- A hosted/cloud eval service or LLM-judged scoring (that is a different product; flux-eval scores
  flux's *own* harness, this tests the *consumer's* agent, local-first, no telemetry).
- Live-datasource anything (owned by D-62/D-168…D-173).
- A general-purpose mocking framework — test-doubles are ordinary registered ops.

## Verification (epic-level)

- Round-trip fidelity property test (capture→save→load→replay is faithful); divergence-latches-loudly
  tests; `serve_nonlatching` miss-without-latch; Resurrect exactly-once (kill a turn mid-op with a
  counting fake op, `resurrect`, assert the side-effect count did not increase); Tune `substitute` →
  `run_diff` shows only the intended `Output` row and `hermetic()==true`.
- End-to-end dogfood: `flux record` a golden of the flux coding agent, commit it, run
  `cargo test --features test-kit` with a deny-all approver + never-called provider, assert green +
  `assert_cost_under` ≈ $0; then edit the system prompt and show `check()` flags a `DiffRow::Plan`.
- Gate: full workspace gate green (both workspaces), clippy `-D warnings`, fmt, `cargo test -p flux-codegate`.
